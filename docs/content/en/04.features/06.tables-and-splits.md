Rendering large enterprise data tables that span multiple printed sheets is a historically difficult problem in browser engines. Printedjs provides native table splitting with repeated headers, cross-page `rowspan` continuation cells, and column width synchronization.

## 1. Repeating Table Headers (`<thead>`)

When a `<table>` is sliced across page boundaries, Printedjs automatically clones and restamps the `<thead>` at the top of every subsequent page segment when repetition is enabled via `class="repeat-header"` or `data-repeat="true"`:

```html
<table class="repeat-header" data-repeat="true">
	<thead>
		<tr class="columns-header">
			<th>SKU</th>
			<th>Product Name</th>
			<th style="text-align: right;">Quantity</th>
		</tr>
	</thead>
	<tbody>
		<!-- Multi-page row content -->
	</tbody>
</table>
```

### Automatic Table Features

- **Multi-Row Header Preservation:** Complex multi-row `<thead>` structures with `colspan` attributes are duplicated intact on every page break.
- **Footer Stamping (`<tfoot>`):** The `<tfoot>` is rendered cleanly at the conclusion of the table on the final page segment.
- **Row Break Protection:** Standard practice to prevent split table rows:
  ```css
  tr {
  	break-inside: avoid;
  }
  ```

## 2. Cross-Page Rowspan Continuation

In conventional browsers, a table cell with `rowspan="5"` that gets split across a page boundary causes severe visual corruption: subsequent columns on the next page shift horizontally because the spanning cell was left on the previous page.

Printedjs solves this automatically by synthesizing continuation cells when `class="repeat-rowspan"` or `data-repeat="true"` is enabled on the table, and preserves category labels across breaks when `data-repeat-content="true"` is set on the spanning cell:

```html
<table class="repeat-header repeat-rowspan" data-repeat="true">
	<thead>
		<tr>
			<th>Subsystem</th>
			<th>Engine Module</th>
			<th>Verification Target</th>
			<th>Status</th>
		</tr>
	</thead>
	<tbody>
		<tr>
			<!-- Multi-row cell cleanly sliced across page boundaries with category label preservation -->
			<td rowspan="5" class="category-cell" data-repeat-content="true">
				Table Fragmentation
			</td>
			<td>thead Duplication Pipeline</td>
			<td>Header restamping on subsequent sheets</td>
			<td>Verified</td>
		</tr>
		<tr>
			<td>Row Integrity Guard</td>
			<td>Guaranteed break-inside avoid atomicity</td>
			<td>Verified</td>
		</tr>
		<!-- Page break boundary occurs naturally across multi-row spans -->
		<tr>
			<td>Rowspan Continuation</td>
			<td>Synthetic continuation cell synthesis</td>
			<td>Verified</td>
		</tr>
	</tbody>
</table>
```

::

### How Rowspan Continuation Works

1. **Geometry Measurement:** The adapter tracks the remaining row budget of active `rowspan` cells when a page split occurs.
2. **Synthetic Continuation Cell:** On the top of the next page, a continuation cell is inserted into the first row with matching width, classes, and styles.
3. **Continuation Indicator:** A subtle continuation marker (or `(continued)` label) can be styled to inform readers that the section originated on the preceding sheet.
